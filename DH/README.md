# DH 连杆系下的辨识参数（Pinocchio 形式）

> 由 `tools/dh_params_doc.py` 生成，数值取自控制器的 `DeviceConfig.yaml`，**勿手改**。
> 重新生成：`python3 tools/dh_params_doc.py`

## 0. 怎么用（路线 1）

`tools/dh_urdf.py` 生成的 `litearm_dh.urdf` 已经把**每个连杆坐标系重建成了控制器的
改进 DH（Craig/MDH）连杆系**。所以下表的参数**不需要任何坐标变换**——按关节号
贴到对应的连杆上即可，它们本来就定义在那个系里。

具体怎么贴见第 1 节；但先看第 2 节的警告：这组惯量**不能**用 `pin.Inertia(m,c,I)` 构造。

挂上新模型：把 config 里的 `model.urdf_path` 从
`../assets/litearm/urdf/litearm.urdf` 改成 `../../../DH/litearm_dh.urdf`
（相对 `src/pylitearm/config/` 解析；`mesh_package_dir` **不用动** ——
网格是 `package://litearm/meshes/...`，按包目录解析，与 URDF 放哪无关）。

### 0.1 3D 预览器里看不到模型 —— `DH/litearm` 符号链接别删

URDF 本身没问题（有 9 个 `<visual>`，网格引用与原文件逐字相同）。空的成因是
`package://litearm/meshes/...` 这个包名**只能靠「从 URDF 所在目录往上找名为 `litearm`
的目录」来解析**：原文件在 `assets/litearm/urdf/` 下，往上第二级就是包根
`assets/litearm/`，命中；`DH/` 往上则没有，于是网格全部加载失败，预览出来是空场景。

所以本目录下的 `litearm` 是指向 `../src/pylitearm/assets/litearm` 的符号链接（相对链接，
仓库内移动仍然有效），**删掉预览就会重新变空**。它只是个解析用的入口，没有复制 61 MB
网格，也不会和原网格产生版本漂移。Pinocchio 侧与它无关：`mesh_package_dir` 是运行时
参数，`package_dirs=` 直接把 `package://litearm` 映射到包根，不看 URDF 放在哪。
关节角约定不变（新 URDF 的轴取 `axis = s_i·z`，`R(-z,q) = R(z,-q)`，
故 `q_new ≡ q_old`），`q_min/q_max`、`direction`、`zero_offset_rad`、
examples/tests 里的硬编码角度、历史录制数据**都不用改**。

### 0.2 ⚠️ 本目录有两套不同的数，别混

| 文件 | 装的是什么 | 来源 |
|---|---|---|
| `dh_params.yaml`、下文第 1/3 节的表 | **辨识参数** | `~/下载/SE1/robot_config/DeviceConfig.yaml`（辨识工具输出） |
| `litearm_dh.urdf` | **厂商 URDF 原有惯量**，逐字未动 | `assets/litearm/urdf/litearm.urdf` |

`litearm_dh.urdf` 只重建了**连杆坐标系**（惯量原点跟着转），**没有把辨识参数写进去**。
例如 joint2 的质量：URDF 里仍是厂商的 `0.296281`，辨识给的是 `1.0`。
所以**直接加载 `litearm_dh.urdf` 得到的是厂商动力学，不是辨识动力学**。

危险之处是**它不会报错**：厂商那套数值本身物理合法，建模型、算 RNEA 全都正常跑，只是数是错的。
要用辨识参数必须显式注入，见第 1a 节。

另外，辨识只覆盖 7 个活动关节：`base_link`/`ee_link` 没有对应的辨识值，注入后它们保留厂商值。

## 2. ⚠️ 为什么不能写 `pin.Inertia(m, c, I)`

```python
import numpy as np, pinocchio as pin

# joint2 的辨识值（见第 1 节表格）
m = 1
c = np.array([0.0527914515216696, 0.648081280744589, 0])
I = np.array([
    [-1.17575708962068, 0.0255899977007594, -0.0223129780822324],
    [0.0255899977007594, -0.00278693735376478, 0.0211291862204379],
    [-0.0223129780822324, 0.0211291862204379, -1.22121556690479],
])

try:
    pin.Inertia(m, c, I)
except RuntimeError as e:
    print("构造失败:", e)          # -> The 3d inertia should be positive.

# 换 FromDynamicParameters 就没问题（它不校验正定性）
pi2 = np.array([m, m * c[0], m * c[1], m * c[2],
                I[0, 0], I[0, 1], I[1, 1], I[0, 2], I[1, 2], I[2, 2]])
print("FromDynamicParameters OK, mass =",
      pin.Inertia.FromDynamicParameters(pi2).mass)
```

Pinocchio 的 `Inertia` 构造函数会做正定性校验，而这组 `ixx..izz` 里有多个负值
（joint2 的 `ixx=-1.176`、`izz=-1.221`；joint4 的 `ixx=-0.411`、`izz=-0.439`），
特征值也全为负。**任何真实刚体的惯量张量都必须半正定**，所以：

- 这组 `ixx..izz` **不是逐连杆的物理惯量**；
- 更像是最小参数集（**base parameters** / 基准参数）的分组结果 ——
  基准参数是若干物理量的线性组合，取负号很常见。
  旁证：`fc1 ≈ −fc0`（正负向摩擦近似反对称）、`cmz` 全为 0、`m` 全为 1。

**这意味着第 1 节的用法能跑，但不保证动力学正确。** 判断方法见第 5 节。

这些量定义在**关节空间**，与连杆系无关，所以新旧 URDF 下数值相同。
注意这里能「直接照搬」靠的是 q 约定没变（第 0 节）：新 URDF 的关节轴取
`axis = s_i·z`，使 `q_new ≡ q_old`。**如果当初为了对齐轴方向而翻了 q 的符号，
`fc0`/`fc1` 就必须互换**（它们分别对应 dq>0 和 dq<0），而 `fv`/`jm` 是 dq、ddq 的
偶函数不受影响。本方案不需要这步。
两点观察（供参考，工具本身没给文档）：

- 每个关节的 `fc1 ≈ −fc0`，像是**符号不对称的库仑摩擦**：正向系数 `fc0`、
  反向系数 `fc1`（理想对称时应互为相反数）。
- `fv2`、`fv3` 在全部 7 个关节上都是 0，说明本次辨识没启用高阶速度项。

即最可能的力矩模型是：

```
τ = τ_惯量/重力/科氏 (RNEA)  +  fv·dq  +  jm·ddq  +  fc0·[dq>0] + fc1·[dq<0]
```

**`fv` 是乘 `dq` 还是乘 `sign(dq)`、`fc0/fc1` 的确切作用（常数？乘 `sign`？）
没有文档，务必用实测力矩对拍确认**（见第 5 节）。

## 4. 坐标变换量（别人问起时的依据）

新旧连杆系之间的常量变换 `C_i`（满足 `M_new = C_i · M_old`）已由
`tools/dh_urdf.py` 解出并写进 URDF，自检通过。三个独立佐证：

- 控制器 `axis.direction` = `[T,T,T,F,T,F,F]`，与从几何（FK 螺旋轴）
  独立解出的关节符号 `[+1,+1,+1,−1,+1,−1,−1]` **逐位一致**。
- 控制器的 `tool`（`x=-0.05375`、`p=-π/2`，定义在 DH 第 7 系）经 `C_7` 映射后，
  正好落在本项目 `ee_link` 的位置与姿态上。
- 项目 URDF 的 joint6 本来就用 `axis="0 0 -1"`，与本方案的符号处理同源。

## 5. 假设与待验证项

这几条**没有被工具文档确认**，是本文件基于数值的推断。先跑起来，再逐条对账：

1. **`m = 1.0` 是工具输出格式的归一化，不是真质量。**
   7 个关节全是 1.0，且另一份 `DeviceConfig_1.yaml` 也是 1.0 —— 不可能是真值。
   好处是 `cm*` 同时等于「质心位置」和「一阶矩」，两种读法数值相同，
   所以这个不确定性**不影响**第 1 节的数值。
   但**真质量没给**，`pin.Inertia` 的 `mass` 一栏只能填 1.0。

2. **若真质量不是 1，重力项会被整体缩放。**
   最直接的验证：让臂停在几个姿态，比较 `pin.computeGeneralizedGravity`
   的预测值与实测保持力矩（扣掉摩擦）。若整体差一个常数倍数，
   那个倍数就是真实总质量相对 1.0 的比例。

3. **部分惯量为负**（如 joint2 的 `ixx=-1.176`、joint4 的 `ixx=-0.411`），
   任何物理连杆的惯量张量都必须半正定，所以这组 `ixx..izz`
   **不太可能是逐连杆的物理惯量**，更像是**最小参数集（base parameters）**
   的分组结果 —— 基准参数是若干物理量的线性组合，取负号很正常，
   而且 `fc1 ≈ −fc0`、`cmz` 全为 0 也符合这个特征。
   若确实如此，**逐连杆赋值 `pin.Inertia` 不会有正确的动力学**，
   正确的用法是把它们当作基准参数去构造回归矩阵。
   判断方法：跑一次 RNEA，和实测力矩比 —— 若量级/形状都对，就是物理惯量；
   若差得远，就是基准参数。

4. **`cmz` 全为 0**：7 个关节都是。若是建模时的约定（DH 的 z 沿轴，
   质心在轴上的分量不可辨识），这是正常的；否则同上，指向基准参数。

5. **重力加速度**：控制器用 `g = 9.802`（`gravity.z`），
   而 Pinocchio 默认 `9.81`。差 0.08%，做对拍时记得统一。

`tools/dh_urdf.py` 的自检把新旧模型做了**端到端物理等价**验证：
